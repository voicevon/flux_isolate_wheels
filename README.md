# flux_loader

`flux_loader` 是一个基于 ESP32 的步进电机控制与物料传输系统。该系统通过精确控制 8 个步进电机，驱动 8 个一体化托架转轮，实现物料（芦笋/Asparagus）的节拍式顺序传输与分发。

---

## 1. 硬件架构与控制

- **核心控制器**：ESP32
- **执行机构**：8 个步进电机（分别控制 8 个托架转轮）
- **机械结构**：
  - 系统包含 8 个托架转轮（托架与转轮一体化设计）。
  - **托架转轮编号**：从右向左依次为 **1号托架转轮** 至 **8号托架转轮**。
  - **传输方向**：物料（芦笋）由左向右依次传输，即：
    $$\text{8号托架转轮} \rightarrow \text{7号} \rightarrow \text{6号} \rightarrow \text{5号} \rightarrow \text{4号} \rightarrow \text{3号} \rightarrow \text{2号} \rightarrow \text{1号}$$

---

## 2. 物料状态定义

对于任意托架转轮上的芦笋数量，系统主要关心以下三种状态：
1. **0 个芦笋**：表示托架为空。
2. **1 个芦笋**：表示托架上仅有单个芦笋。
3. **2 个及以上芦笋（2+）**：多物料状态（2 个与 2 个以上在业务处理逻辑中视为相同状态）。

---

## 3. 业务控制逻辑（托架状态机）

系统按**节拍**运行：每个 `load` 命令携带 8 个托架的芦笋数量，设备对每个托架按**七态状态机**（自由/上岗/接客/美妙/超载/锁定/轮回）判定，规划最多 3 个节拍的动作；每拍内 8 路电机同时启动，全部到位后应答 done。

核心判定（编号与 doc/节拍逻辑.md 对应）：

1. **按自身数量**（自由/上岗）：数量=1 → 美妙；≥2 → 超载；=0 → 上岗
2. **上岗判定**：右邻有料 → 锁定（优先）；否则左邻有料 → 接客；否则保持上岗
3. **右邻有料**：美妙/接客/超载一律锁定，本拍不投料（防堆积）
4. **超载 → 轮回**：先转 60° 分解多料，完成后按右邻有无料进入锁定或自由
5. **右邻被锁定**（空轮不转）时，有料托架同样锁定，不把料投给不动的轮子
6. **节拍动作**：接客 30°+60°、美妙 60°+30°、轮回 60°、锁定/上岗不动；未锁定的接客/美妙到位后回自由，锁定在下次 load 解除

> 状态判定流程、节拍生命周期、参数速查与示例推演见 **[doc/节拍逻辑.md](doc/节拍逻辑.md)**。

---

## 4. 多电机执行策略

8 个步进电机各接**独立 STEP 引脚**，由 FastAccelStepper 独立控制加减速，同一节拍内**同时启动、各走各的目标步数**（减速比 54:18 = 3:1，1/16 细分下 90° = 2400 步、60° = 1600 步、30° = 800 步，均为电机轴步数）。方向信号经 74HC595 串行输出；驱动器使能脚 (EN) 直接接地常使能，无软件使能概念。各电机的逻辑方向与物理方向映射由 `DIR_INVERT_MASK`（config.h）逐机配置，安装反向的电机自动求反。

> **细分设置**：所有驱动器共用同一组细分控制引脚（MS1 / MS2 / MS3），统一配置为 1/16 细分。

## 5. 接口与引脚定义 (GPIO)

| 功能 | GPIO | 说明 |
| :--- | :--- | :--- |
| STEP0 ~ STEP7 | 13, 12, 14, 27, 26, 25, 33, 32 | 8 路电机独立步进脉冲 |
| MS1 / MS2 / MS3 | 4 / 16 / 17 | 细分选择（全核共用） |
| 74HC595 数据 (DS) | 21 | DIR 串行输出 |
| 74HC165 数据 (Q7) | 34 | HOME 串行输入 |
| 移位时钟 (SHCP/CP) | 19 | 595 与 165 共享 |
| 锁存 (STCP/PL) | 18 | 595 与 165 共享 |
| 入口光电传感器 | 39 | 检测物料落入入口 |
| 板载 LED | 2 | 心跳/诊断指示 |
| 驱动器 EN | — | 接地常使能，未接 GPIO |
