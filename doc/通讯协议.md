# flux_loader 通信协议（设备 ↔ 上位机约定）

> 本文档是 ESP32 输送设备与上位机（手机 / PC）之间的**通信约定**，上位机开发以本文为准。
> 约定版本：v1.2（2026-09-22）。变更须同步更新版本号。
>
> **v1.1 变更**：新增 `motor` 单电机调试命令；`done` 应答增加 `cmd` 字段回带命令类型。
> **v1.2 变更**：新增 `multi` 多电机同时调试命令（每电机独立角度，负值反转）。

## 1. 连接参数

| 项目 | 值 |
| :--- | :--- |
| 传输方式 | WiFi + MQTT |
| Broker | `voicevon.vicp.io` |
| 端口 | `1883`（无 TLS） |
| 用户名 / 密码 | `von` / `von123456` |
| 设备 ID（devid） | 设备 ESP32 MAC 后 4 位十六进制，**当前设备为 `F8EC`** |
| Keepalive | 15 秒 |

## 2. 主题定义

所有主题前缀为 `flux/loader/{devid}/`，共 4 个：

| 主题 | 方向 | QoS | 说明 |
| :--- | :--- | :--- | :--- |
| `cmd` | 上位机 → 设备 | 0 | 节拍命令（设备订阅） |
| `done` | 设备 → 上位机 | 0 | 节拍完成应答 |
| `state` | 设备 → 上位机 | 0 | 运行状态，**保留消息**；异常掉线由遗嘱代发 `offline` |
| `log` | 设备 → 上位机 | 0 | 固件日志实时输出（文本行，与串口日志同源） |

## 3. 下行命令（cmd）

设备按载荷中的 `cmd` 字段区分命令类型，当前支持三种：

| cmd 值 | 用途 |
| :--- | :--- |
| `load` | 生产节拍：按 8 托架物料数量执行业务旋转 |
| `motor` | 调试：单电机按指定方向、角度旋转 |
| `multi` | 调试：多电机同时按各自角度旋转（v1.2） |

### 3.1 生产命令（load）

```json
{"cmd":"load","counts":[1,0,2,0,1,0,0,3]}
```

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `cmd` | string | 是 | 固定为 `"load"` |
| `counts` | int[8] | 是 | 长度**必须为 8**，依次为 **1 号至 8 号托架**的芦笋数量 |

### 3.2 counts 取值约定

- 非负整数；业务上仅区分 **0 / 1 / ≥2** 三种情形，更大的数值按 ≥2 处理。
- counts 顺序与托架编号严格对应：`counts[0]` = 1 号托架，`counts[7]` = 8 号托架。
- 各托架的旋转角度由设备固件业务规则决定，上位机无需计算，只负责提供数量。

### 3.3 受理规则（双方遵守）

1. 设备仅在 `state = idle` 时受理命令；`running` 期间收到的命令**被忽略**（仅记日志，不做错误回执）。
2. 一帧命令触发**一个节拍**，节拍结束发布 `done`。
3. 上位机连续发送是允许的，但未受理的帧会被丢弃；**稳妥模式：收到 `done` 后再发下一帧**。
4. 格式非法（缺字段、数组长度不为 8、非 JSON）的载荷同样被忽略并记入 `log`。

### 3.4 调试命令（motor）

```json
{"cmd":"motor","motor":5,"dir":1,"angle":90}
```

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `cmd` | string | 是 | 固定为 `"motor"` |
| `motor` | int | 是 | 电机号，**1-8**（托架编号，1 号 = counts[0] 对应的电机） |
| `dir` | int | 是 | 方向：`1` = 正转，`0` = 反转 |
| `angle` | number | 是 | 旋转角度（度），范围 (0, 360]，支持一位小数（如 `22.5`） |

行为约定：

1. 仅 `state = idle` 时受理，受理后设备以**调试低速**驱动该电机，完成后发 `done`（`cmd` 回带 `"motor"`）并恢复生产速度参数。
2. 角度换算在设备端完成（1/16 细分、3:1 减速，90° = 2400 步），上位机只给角度。
3. 字段越界（电机号非 1-8、dir 非 0/1、角度超范围）或缺失时命令被忽略并记入 `log`。

### 3.5 多电机调试命令（multi，v1.2）

```json
{"cmd":"multi","angles":[90,-45,0,0,0,22.5,0,360]}
```

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `cmd` | string | 是 | 固定为 `"multi"` |
| `angles` | number[8] | 是 | 长度**必须为 8**，依次为 **1 号至 8 号电机**的旋转角度（度） |

取值与行为约定：

1. `angles[i]` 范围 **[-360, 360]**，支持一位小数；**0 = 该电机不动作**，**正值 = 正转**，**负值 = 反转**。
2. 仅 `state = idle` 时受理；全部非零电机**同时启动**、以调试低速运行，全部到位后发 `done`（`cmd` 回带 `"multi"`）并恢复生产速度参数。
3. 角度换算在设备端完成（1/16 细分、3:1 减速，90° = 2400 步）。
4. 全零数组为合法命令：设备不做任何运动，直接回 `done`。
5. 长度不为 8、含越界角度或非 JSON 的载荷被忽略并记入 `log`。

## 4. 上行消息

| 消息 | 载荷示例 | 触发条件 |
| :--- | :--- | :--- |
| `done` | `{"event":"done","cmd":"load"}` | 节拍完成；`cmd` 回带触发本次节拍的命令类型（`load` / `motor` / `multi`） |
| `state` | `{"state":"idle"}` | 空闲（保留消息，订阅即收） |
| `state` | `{"state":"running"}` | 节拍执行中 |
| `state` | `{"state":"offline"}` | **仅由遗嘱消息（LWT）产生**：设备异常掉线时 broker 自动发布 |
| `log` | `[INFO] 接收到芦笋数据: 1号=0, ...` | 固件内所有 INFO / WARN / ERROR 日志 |

状态机（上位机视角）：

```
        收到 cmd（idle 时才受理）            全部电机到位
idle ────────────────────────────▶ running ────────────────▶ 发 done，回 idle
  ▲                                                             │
  └─────────────────────────────────────────────────────────────┘
```

## 5. 上位机集成约定

1. **完成判定只认 `done` 主题**，不得用固定延时替代（单拍时长约 0.3 ~ 1 秒，随动作电机组合浮动；一次 load 最多三拍、约 2 ~ 3 秒；单机调试命令 90° 约 3 秒）。
2. 订阅 `state` 后会**立即收到一条保留消息**，据此初始化设备状态，不要假设初始状态。
3. 判活：收到 `offline` 遗嘱即离线；未收到遗嘱即认为在线。
4. 多设备发现：订阅通配符 `flux/loader/+/state`，保留消息会列出所有在线设备。
5. JSON 解析须容忍字段顺序变化，未知字段一律忽略（向后兼容预留）。

## 6. 测试接口（mosquitto 命令行）

### 6.1 监听设备全部回传

```bash
mosquitto_sub -h voicevon.vicp.io -p 1883 -u von -P von123456 \
  -t "flux/loader/F8EC/state" -t "flux/loader/F8EC/done" -t "flux/loader/F8EC/log" -v
```

### 6.2 发送一个节拍命令

```bash
mosquitto_pub -h voicevon.vicp.io -p 1883 -u von -P von123456 \
  -t "flux/loader/F8EC/cmd" \
  -m "{\"cmd\":\"load\",\"counts\":[1,0,2,0,1,0,0,3]}"
```

**预期**：`state` → `running` → 电机动作 → `state` 回 `idle` → 收到 `done`。

### 6.3 发现所有在线设备

```bash
mosquitto_sub -h voicevon.vicp.io -p 1883 -u von -P von123456 -t "flux/loader/+/state" -v
```

### 6.4 边界命令（全零 counts）

```bash
mosquitto_pub -h voicevon.vicp.io -p 1883 -u von -P von123456 \
  -t "flux/loader/F8EC/cmd" \
  -m "{\"cmd\":\"load\",\"counts\":[0,0,0,0,0,0,0,0]}"
```

> 注意：全零 counts 是**全机不动**的合法命令——8 个托架全部判定为“上岗”，设备**不做任何运动**，立即回 `done`（实测约 0.2 秒内）。常用于联通性测试。规则详见 [节拍逻辑](节拍逻辑.md)。

### 6.5 单电机调试（5 号电机正转 90°）

```bash
mosquitto_pub -h voicevon.vicp.io -p 1883 -u von -P von123456 \
  -t "flux/loader/F8EC/cmd" \
  -m "{\"cmd\":\"motor\",\"motor\":5,\"dir\":1,\"angle\":90}"
```

反转 22.5° 示例：把 `"dir":1,"angle":90` 换成 `"dir":0,"angle":22.5`。`done` 应答中 `cmd` 为 `"motor"`。

### 6.6 多电机同时调试（1 号正转 90°，2 号反转 45°，其余不动）

```bash
mosquitto_pub -h voicevon.vicp.io -p 1883 -u von -P von123456 \
  -t "flux/loader/F8EC/cmd" \
  -m "{\"cmd\":\"multi\",\"angles\":[90,-45,0,0,0,0,0,0]}"
```

`done` 应答中 `cmd` 为 `"multi"`。

### 6.7 前置条件

设备端固件 `src/config.h` 需填入有效的 `WIFI_SSID` / `WIFI_PASSWORD` 并重新烧录，否则设备不上线。
