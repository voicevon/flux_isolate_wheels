# flux_loader 节拍逻辑详解

> 本文档解释固件"节拍"（beat）的完整执行逻辑，供维护固件与联调上位机时参考。
> 业务规则速览见 [README](../README.md) 第 3 节；命令/应答报文格式见 [通讯协议](通讯协议.md)。
> 按三拍分解的图形化流程见 [节拍状态图](节拍状态图.md)。
> 依据代码：`src/AppProduction.cpp`。
> 第 4 节托架状态机已在固件中实现（2026-09-23），旧的 90°/22.5° 规则已移除。

## 1. 什么是节拍

节拍 = 一个 `load` 命令触发的一次完整物料输送动作：

```
上位机发 load 命令（携带 8 托架芦笋数量）
    → 设备按托架状态机规划动作（30° / 60° / 90° / 不动）
    → 节拍1 → 节拍2 → 节拍3 顺序执行，每拍内 8 路电机同时启动
    → 三拍全部到位后发 done 应答
```

单机调试命令 `motor`（单电机）与 `multi`（8 路角度数组）复用同一节拍生命周期（IDLE→RUNNING→COMPLETED），但不做业务规划，仅按命令直接驱动电机。

## 2. 节拍生命周期（状态机）

```
        load/motor 命令（仅 idle 受理）         全部电机到位
 IDLE ────────────────────────────▶ RUNNING ────────────────▶ COMPLETED
  ▲                                                              │
  │         stop → (调试节拍恢复速度) → 发 done → 发 state:idle    │
  └──────────────────────────────────────────────────────────────┘
```

| 状态 | 行为 | MQTT 输出 |
| :--- | :--- | :--- |
| `IDLE` | 等待命令；收到合法命令即规划并启动 | — |
| `RUNNING` | 按节拍1→2→3 顺序执行，每拍轮询 `isMoving()`，全部电机到位后进入下一拍 | 进入时发 `state: running` |
| `COMPLETED` | 停止电机；调试节拍恢复生产速度参数；发布应答 | `done`（回带 cmd 类型）+ `state: idle`，随后回 `IDLE` |

**并发约束**：`RUNNING` 期间收到的命令一律忽略（仅记 `log`），不做队列缓存。

## 3. 命令受理与校验（load）

1. 仅 `IDLE` 状态受理。
2. JSON 必须含 `"cmd":"load"` 和 `"counts"` 数组；数组解析出 **恰好 8 个 0~255 的整数**，数量不足 8 个、含负数 / 超 255 / 带小数的值时，整帧忽略并记 `log`。
3. 解析成功即改写当前托架状态缓存 `_asparagusCounts[8]`，随后进入运动规划。
4. 业务上只区分 0 / 1 / ≥2 三种状态；数值大小无更细含义。

## 4. 运动规划规则（托架状态机）

**物理现实与拓扑定义**：
- 物料（芦笋）由左向右依次传输；
- 物理托架编号从左向右依次为 **1 号轮至 8 号轮**（1 号在最左端进料，8 号在最右端出料）；
- 数组索引 0~7 对应托架 1~8 号；
- **"右侧" = 托架编号加一（更靠近出料口一侧，索引加一）**，**"左侧" = 托架编号减一（靠近进料口一侧，索引减一）**；
- 1 号轮在最左侧（没有左邻），8 号轮在最右侧（右侧紧邻出料口）。

### 4.1 配对规则（双轮成对产生）

动作以**供方（左）→ 接收方（右，编号加一）**成对产生，要么成对、要么整对不产生：

1. **供方条件**：当前处于**锁定**且自身芦笋数量 $\ge 1$，或者处于**转世**（上一拍超载分解后）。
2. **接收方条件**（供方右侧相邻轮 $r = i + 1$）：
   - 接收方处于**锁定**；
   - 接收方为空（$count = 0$）；
   - 接收方的右侧无料（即接收方“可以解锁”）：若 $r < 7$ 则要求 $count[r+1] == 0$；若 $r == 7$（8号轮作为接收方），其右侧为出料口，永远无料。
3. **8号轮出料特权**：8 号轮（$i = 7$）自身为供方时，其接收位即为出料口（虚拟接收位，永远为空、可解锁），永远可配对出料。
4. **配对产生分支**：
   - **锁定 + count=1 → 美妙 + 接美妙**：供方走美妙，接收方走接美妙；
   - **锁定 + count≥2 → 超载 + 接超载**：供方走超载（终态转世），接收方走接超载（终态锁定）；
   - **转世 → 新生 + 接新生**：供方走新生（终态锁定），接收方走接新生（终态锁定）。
5. **不成对处理**：不成对则整对不动作，双方保持原状态不变。

### 4.2 节拍动作（单次 load 内三拍执行）

一次 load 内按 节拍1 → 节拍2 → 节拍3 顺序执行；每个节拍内全部电机同时启动，各走各的步数。表中角度为单拍增量步数对应的绝对角度：

| 状态 | 节拍1 | 节拍2 | 节拍3 | 终态 | 累计角度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **美妙**（供方） | 旋转 60° | 空拍（不动） | 旋转 30° | 锁定 | 90° |
| **接美妙**（接收方） | 旋转 30° | 旋转 60° | 空拍（不动） | 锁定 | 90° |
| **超载**（供方） | 旋转 28° | 空拍（不动） | 空拍（不动） | 转世 | 28° |
| **接超载**（接收方） | 空拍（不动） | 旋转 90° | 空拍（不动） | 锁定 | 90° |
| **新生**（供方） | 旋转 32° | 空拍（不动） | 旋转 30° | 锁定 | 62° |
| **接新生**（接收方） | 旋转 30° | 旋转 60° | 空拍（不动） | 锁定 | 90° |
| **锁定 / 保持** | 不动 | 不动 | 不动 | 保持 | 0° |

三拍全部完成后发布 `done` 应答并回到 `idle`。

## 5. 执行模型

- **8 路独立 STEP**：每台电机独立 FastAccelStepper 通道，独立加减速，同一节拍**同时启动、各走各的步数**；不存在共享脉冲分阶段机制。
- **方向**：74HC595 一次输出 8 位方向数据。生产节拍全体逻辑正转（`0xFF`）；单机调试按命令置位。输出前经 `DIR_INVERT_MASK`（config.h）逐机求反，换算为物理方向。
- **到位判定**：主循环检测 `isMoving() == false`（所有通道都到达目标步数）。
- **完成动作**：停止全部电机 → 若为调试节拍则恢复生产速度/加速度 → 发布 `done` → 发布 `state: idle`。

## 7. 示例推演

### 例 1：`counts = [0, 0, 0, 0, 0, 0, 0, 1]`（8号轮出料）

- **初始状态**：8号轮锁定 + count=1。
- **判定**：8 号轮右侧为出料口（虚拟接收位，永远为空且可解锁）→ 8 号轮判定为**美妙**向出料口出料。
- **节拍动作**：
  - 节拍1：8号轮旋转 60°；
  - 节拍2：空拍；
  - 节拍3：8号轮旋转 30°。
- **结果**：8 号轮物料完成出料，恢复锁定。

### 例 2：`counts = [1, 0, 0, 0, 0, 0, 0, 0]`（1号轮向2号轮美妙配对）

- **初始状态**：1号轮锁定 + count=1；2号轮锁定 + count=0；3号轮 count=0。
- **判定**：1号轮为供方，2号轮为接收方。2号轮为空且其右侧（3号轮）无料，可解锁 → **1号轮与2号轮美妙配对**！
- **节拍动作**：
  - 1号轮（供方）：美妙（拍1 转 60°，拍3 转 30°）；
  - 2号轮（接收方）：接美妙（拍1 转 30°，拍2 转 60°）。
- **结果**：物料由 1 号轮顺利转移至 2 号轮。

### 例 3：`counts = [0, 2, 0, 0, 0, 0, 0, 0]`（2号轮超载配对）

- **判定**：2号轮锁定 + count=2（超载供方），3号轮锁定 + count=0（接收方），4号轮 count=0 → **2号轮与3号轮超载配对**！
- **节拍动作**：
  - 2号轮（供方）：超载（拍1 转 28°，拍2/3 不动，终态转世）；
  - 3号轮（接收方）：接超载（拍1 不动，拍2 转 90°，拍3 不动，终态锁定）。
- **后续**：下一节拍 2 号轮为“转世”，将与后续空轮产生“新生 + 接新生”配对完成余料输送。
